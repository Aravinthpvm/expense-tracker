# Smart Expense Tracker API

A REST API for managing personal expenses, built for the Diligent Software
Engineering Apprenticeship 2026 take-home assignment.

## Stack

- Java 17
- Spring Boot 3.3.2 (Web + Validation)
- Maven
- In-memory storage (`ConcurrentHashMap`) — no database required, data resets on restart
- JUnit 5 + Spring Boot Test + AssertJ for tests

## Prerequisites

- JDK 17+
- Maven 3.9+ — or just use the bundled wrapper below, no local Maven install needed

## Install dependencies

```bash
./mvnw -q dependency:go-offline
```

## Run the server

```bash
./mvnw spring-boot:run
```

The server starts on **http://localhost:8080**.

### OpenAPI / Interactive Swagger Docs (Bonus Feature)

When the server is running, you can access the interactive Swagger UI to explore and test the endpoints directly from your browser:
* **Interactive UI**: http://localhost:8080/swagger-ui/index.html
* **OpenAPI Specs (JSON)**: http://localhost:8080/v3/api-docs

## Run the tests

```bash
./mvnw test
```

(On Windows, use `mvnw.cmd` instead of `./mvnw`. If you have Maven installed
system-wide, plain `mvn` works too.)

## API Reference

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/expenses` | Add an expense |
| GET | `/api/expenses` | List all expenses |
| GET | `/api/expenses?category=Food` | List expenses filtered by category (case-insensitive) |
| GET | `/api/expenses/total` | Total of all expenses |
| GET | `/api/expenses/total?category=Food` | Total for one category |
| DELETE | `/api/expenses/{id}` | Delete an expense by id |

### Add an expense

```bash
curl -X POST http://localhost:8080/api/expenses \
  -H "Content-Type: application/json" \
  -d '{"title":"Coffee","amount":4.50,"category":"Food","date":"2026-07-31"}'
```

Response `201 Created`:

```json
{
  "id": "b3f1c2...-uuid",
  "title": "Coffee",
  "amount": 4.50,
  "category": "Food",
  "date": "2026-07-31"
}
```

Note: `id` is always generated by the server — it is not accepted in the request body,
so a client can never overwrite an existing record by guessing or reusing an id.

### List / filter

```bash
curl http://localhost:8080/api/expenses
curl http://localhost:8080/api/expenses?category=Food
```

### Totals

```bash
curl http://localhost:8080/api/expenses/total
curl http://localhost:8080/api/expenses/total?category=Food
```

### Delete

```bash
curl -X DELETE http://localhost:8080/api/expenses/b3f1c2...-uuid
```

Returns `204 No Content` on success, `404 Not Found` if the id doesn't exist.

## Validation

- `title` and `category` must not be blank.
- `amount` must be greater than 0.
- `date` must be a valid ISO date (`YYYY-MM-DD`).
- Invalid input returns `400 Bad Request` with a JSON error body describing the problem.

## Design notes

- Ids are server-generated UUIDs, not client-supplied, to keep the API safe from
  accidental or malicious overwrite-by-id.
- Category filtering and matching for totals is case-insensitive, since a human
  typing "food" vs "Food" shouldn't produce two different buckets.
- Storage is a single `ConcurrentHashMap` behind a repository interface, so swapping
  in a real database later only touches `ExpenseRepository`.
